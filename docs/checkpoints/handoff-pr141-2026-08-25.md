## Finance freeze incident — root cause and final fix

### Symptom

After recent Finance changes, production could remain on:

`Connecting to SD.Live Track…`

and Safari would eventually become unresponsive.

### Investigation sequence

- PR #137 hardened Finance timeouts/transport and attempted to prevent indefinite loading.
- PR #139 simplified part of the runtime path and reduced duplicate/false connection state behavior.
- PR #140 forced `/admin/finance*` through the Worker, added no-cache behavior and exposed bounded diagnostic state.
- Those changes improved failure handling but did not stop the browser freeze.

### Root cause — PR #141

`admin/finance-liventx-portal-link.js` installed a `MutationObserver` over the entire `document.body` subtree.

Its callback ran synchronization code that rewrote link text/attributes inside that same observed subtree. Those writes could retrigger the observer, causing an unbounded:

`mutation → callback → mutation → callback → …`

loop.

This saturated the browser main thread. Once the main thread was saturated, even browser timeouts could not fire, which made the UI look like an unresolved Google Sheets connection when the primary problem was frontend main-thread starvation.

### Final fix

PR #141:

- removes the DOM-wide `MutationObserver` from the LiventX portal runtime;
- updates portal links only through explicit click, keyboard and language events;
- makes link configuration idempotent;
- cache-busts the affected asset;
- expands Finance freeze regression tests so relevant Finance runtimes cannot reintroduce this DOM-wide observer pattern.
